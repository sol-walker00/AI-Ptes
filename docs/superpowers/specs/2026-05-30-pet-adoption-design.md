# 宠物领养站与桌面客户端导入设计

日期：2026-05-30

## 背景

现有产品已经具备桌面 AI 宠物的核心能力：Tauri 桌面客户端、宠物窗口、设置窗口、聊天窗口、本地宠物状态、模型供应商中心和形象装扮。下一步目标不是重新做一只宠物，而是补上分发闭环：用户从网站设计并领养宠物，下载桌面客户端，再把领养到的宠物带到自己的电脑桌面上。

V1 采用无账号、无后端的轻量路线：领养网站生成 `.pet` 领养档案，桌面客户端首次启动时导入该档案。这个方案能最快验证“从我的网站领养宠物”的核心体验，同时保留未来升级为领养码、深链导入、账号和云同步的空间。

## 产品原则

1. 网站负责宠物出生和分发，桌面客户端负责陪伴和成长。
2. V1 不引入账号、云同步或服务端保存档案。
3. `.pet` 只保存出生档案，不保存 API key、聊天记忆或成长状态。
4. 桌面端导入后生成本地状态，后续成长完全保存在用户本机。
5. 网站第一屏就是创建宠物，不做纯营销落地页。
6. 数据格式要有版本号，便于 V2 兼容旧档案。

## V1 用户体验

用户打开领养网站后，直接进入“创建我的宠物”流程。用户可以设置宠物名字、形象描述、性格、身体、主色、辅色、眼睛、嘴巴、脸颊和配饰。网站实时显示宠物预览。

用户完成设计后，网站生成一个 `adoption.pet` 文件，并提示用户下载桌面客户端。用户安装并首次打开客户端时，如果本地还没有宠物，客户端显示两个入口：

1. 导入我已领养的宠物。
2. 本地创建新宠物。

用户选择导入后，选择 `adoption.pet` 文件。客户端校验文件格式，读取宠物资料，初始化本地状态，然后显示桌面宠物。导入完成后，用户仍需在本机设置模型供应商和 API key；这些敏感信息不会进入 `.pet` 文件。

## 范围

V1 必须包含：

1. 新增 `site/` 领养网站。
2. 网站复用当前宠物头像选项和渲染规则。
3. 网站生成并下载 `.pet` 领养档案。
4. 桌面端新增 `.pet` 数据模型、解析和校验。
5. 桌面端无本地宠物时展示导入入口。
6. 桌面端导入后创建完整本地 `AppData`。
7. 网站提供 macOS 和 Windows 客户端下载入口。

V1 不包含：

1. 用户账号。
2. 云端保存领养档案。
3. 多设备同步。
4. 领养码。
5. `desktop-ai-pet://` 深链导入。
6. 自动更新。
7. 支付、商城或付费换装。
8. 分享页和社区展示。

## 系统结构

### Desktop App

现有 `app/` 继续作为 Tauri 桌面客户端。它负责透明宠物窗口、聊天窗口、设置窗口、模型供应商、API key 安全存储、本地状态、本地记忆和宠物生命周期。

桌面端新增一个领养导入边界：

```text
adoption.pet
-> Adoption parser
-> Adoption validator
-> PetProfile
-> createInitialPetState(createdAt)
-> emptyMemory(createdAt)
-> ensureDailyCare(undefined, createdAt)
-> saveAppData
```

这个边界应该是纯逻辑优先，便于单元测试。UI 只负责选择文件、展示错误和触发导入。

### Adoption Site

新增 `site/` 作为领养网站。网站第一版可以使用 React + TypeScript + Vite，以便复用当前桌面端的头像配置和 SVG 渲染思路。网站只在浏览器本地生成 `.pet` 文件，不需要服务端。

网站由四个核心区域组成：

1. 宠物预览：实时展示当前设计。
2. 设计表单：名字、形象、性格和装扮控制。
3. 领养操作：生成并下载 `.pet`。
4. 客户端下载：macOS 和 Windows 下载按钮。

### Adoption Schema

V1 可以先在桌面端 `domain` 中定义领养档案类型，再由网站复制或共享同一份定义。后续如果 `app/` 和 `site/` 都需要长期维护，应抽成共享包。

## `.pet` 文件格式

`.pet` 文件是 JSON 文档，扩展名用于产品语义。V1 格式如下：

```json
{
  "format": "desktop-ai-pet-adoption",
  "version": 1,
  "adoptionId": "pet_abc123",
  "createdAt": "2026-05-30T12:00:00.000Z",
  "profile": {
    "name": "桃桃",
    "species": "桌面小猫",
    "personaId": "healing",
    "avatar": {
      "body": "cat",
      "primaryColor": "#f6c65b",
      "secondaryColor": "#fff1bf",
      "eyeStyle": "dot",
      "mouthStyle": "cat",
      "cheekStyle": "pink",
      "accessory": "bow"
    }
  }
}
```

字段规则：

1. `format` 必须等于 `desktop-ai-pet-adoption`。
2. `version` 必须是桌面端支持的整数版本，V1 只支持 `1`。
3. `adoptionId` 由网站生成，使用 `pet_` 前缀和随机 ID。
4. `createdAt` 必须是可解析的 ISO 时间字符串。
5. `profile.name` 必须是非空字符串，导入时去除首尾空白。
6. `profile.species` 必须是非空字符串，导入时去除首尾空白。
7. `profile.personaId` 必须是现有性格枚举之一。
8. `profile.avatar` 通过现有 `normalizePetAvatar` 归一化。

导入后，桌面端将 `.pet` 转成现有 `PetProfile`，并使用 `createdAt` 作为宠物创建时间。

## 桌面端数据流

### 首次启动

1. 客户端读取本地 `AppData`。
2. 如果已有 `profile`，继续显示现有宠物。
3. 如果没有 `profile`，显示领养欢迎界面。
4. 用户选择导入 `.pet` 或本地创建。

### 导入 `.pet`

1. 用户选择文件。
2. 前端读取文件文本。
3. 解析 JSON。
4. 校验 `format`、`version`、时间、名字、形象、性格和头像。
5. 生成 `PetProfile`。
6. 生成初始 `PetState`。
7. 生成空 `MemorySummary`。
8. 生成当天 `DailyCare`。
9. 保留当前默认模型设置。
10. 保存完整 `AppData`。
11. 显示导入成功状态并切回宠物窗口。

### 本地创建

本地创建继续使用现有设置窗口能力。V1 可以将它作为导入欢迎界面的次要入口，不改变现有创建和保存逻辑。

## 网站端数据流

1. 网站加载默认宠物档案。
2. 用户调整名字、形象、性格和装扮。
3. 网站实时归一化头像数据并更新预览。
4. 用户点击领养。
5. 网站生成 `adoptionId`、`createdAt` 和领养档案 JSON。
6. 网站用 Blob 下载 `adoption.pet`。
7. 网站提示下载桌面客户端。

网站不需要收集用户邮箱、账号或 API key。

## 错误处理

桌面端导入错误：

1. 文件不是合法 JSON：提示“这个领养档案无法读取”。
2. `format` 不匹配：提示“这不是本产品的领养档案”。
3. `version` 不支持：提示“这个领养档案版本太新，请更新客户端”。
4. 必填字段缺失：提示“领养档案不完整，请重新下载”。
5. 性格不支持：提示“这个宠物性格暂不支持”。
6. 头像字段异常：使用默认值归一化，不阻止导入。
7. 本地保存失败：提示保存失败，不覆盖当前已有数据。

网站端生成错误：

1. 宠物名字为空时禁用领养按钮。
2. 浏览器不支持 Blob 下载时，显示 JSON 文本下载备用说明。
3. 下载链接未配置时，显示“客户端安装包即将开放”，但不影响 `.pet` 下载。

## 安全与隐私

V1 不上传任何宠物档案，也不上传用户 API key。`.pet` 文件只包含用户主动设计的出生档案。桌面端导入后，API key 仍通过系统安全存储保存，聊天记忆和成长状态仍保存在本地应用数据目录。

`.pet` 文件不应包含：

1. API key。
2. 模型供应商密钥。
3. 聊天记录。
4. 长期记忆。
5. 成长状态。
6. 本机路径。
7. 设备信息。

## 测试策略

自动化测试覆盖：

1. 领养档案默认值生成。
2. 合法 `.pet` 可解析为 `PetProfile`。
3. 无效 `format` 被拒绝。
4. 不支持的 `version` 被拒绝。
5. 空名字被拒绝。
6. 不支持的 `personaId` 被拒绝。
7. 异常头像字段通过 `normalizePetAvatar` 回落默认值。
8. 导入后生成初始 `PetState`、空记忆、事件列表和每日任务。
9. 导入失败不会调用保存。
10. 网站点击领养会生成符合 schema 的 JSON 文件。

手动验收覆盖：

1. 打开网站第一屏就是创建宠物。
2. 网站调整装扮后预览同步变化。
3. 网站可以下载 `adoption.pet`。
4. 新安装桌面客户端首次启动时出现导入入口。
5. 导入网站生成的 `.pet` 后，桌面宠物名字、性格和外观正确。
6. 导入后用户仍可设置模型供应商和 API key。
7. 无效 `.pet` 显示清晰错误，不破坏已有本地宠物。
8. macOS 和 Windows 下载按钮在未配置安装包时有明确状态。

## 发布策略

V1 的网站下载按钮使用静态配置：

1. macOS 下载地址。
2. Windows 下载地址。
3. 当前版本号。
4. 发布说明链接。

安装包可以先手动构建并上传到可下载位置。自动更新、签名、公证和 GitHub Releases 自动化属于后续发布工作，不阻塞 V1 领养闭环验证。

## V2 延展

V2 可以在不推翻 V1 的基础上增加：

1. 服务端保存领养档案。
2. 领养码导入。
3. `desktop-ai-pet://adopt?id=pet_abc123` 深链导入。
4. 宠物分享页。
5. 下载统计。
6. 热门模板。
7. 用户账号。
8. 云同步。
9. 自动更新。
10. 安装包签名和发布流水线。

## 成功标准

V1 完成时，用户可以在网站设计一只宠物，下载 `.pet` 领养档案和桌面客户端，并在首次启动桌面客户端时导入该档案。导入后的桌面宠物必须正确显示网站设置的名字、性格和外观。API key、聊天记忆和成长状态必须只存在于用户本机。
