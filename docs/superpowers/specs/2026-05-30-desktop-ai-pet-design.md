# 桌面 AI 宠物产品设计

日期：2026-05-30

## 背景

目标是做一个类似 QQ 宠物的桌面产品，但宠物内部可以置入用户自己的 API key。用户不是打开一个普通 AI 聊天工具，而是在电脑桌面上养一只可以对话、会表达状态、能调用 AI 能力的宠物。

第一版以桌面体验优先，选择 Tauri + React/TypeScript 作为技术路线。Tauri 负责透明悬浮窗口、系统托盘、本地文件读写和安全密钥访问；React 负责宠物舞台、设置页和聊天界面。第一版重点证明“桌宠感”和“宠物化 AI 交互”成立，不做账号系统、云同步、商城、多宠物经济系统或复杂换装。

## 产品原则

1. 宠物是第一界面，聊天框是辅助界面。
2. AI 能力必须被宠物人格、宠物状态和关系记忆包装。
3. API key 属于用户，只保存在本机安全存储中。
4. 第一版支持 OpenAI-compatible API，后续再扩展其他模型。
5. 所有核心状态先本地化保存，避免第一版引入服务端复杂度。

## 核心用户体验

用户首次启动应用时会进入领养流程：给宠物命名，选择基础人格，填入 API key、base URL 和模型名，并通过连接测试。完成后，桌面上出现一个透明背景、置顶、可拖拽的小宠物窗口。

日常使用有两种对话入口：

1. 快速对话：点击宠物，弹出小输入气泡，适合一句话互动。
2. 深度聊天：从宠物菜单或系统托盘打开聊天面板，适合连续对话。

宠物每次回应都同时包含三层结果：

1. 文本回复：由 AI 模型生成，使用宠物口吻。
2. 动作状态：例如思考、开心、困惑、撒娇、疲惫。
3. 状态变化：例如亲密度上升、精力下降、心情变化。

## 宠物化 AI 交互

本质上，用户是在和 AI 交互；产品体验上，用户是在和宠物交互。每次 AI 请求都由 Pet Brain 组装上下文：

```text
用户输入
-> 宠物人格：性格、说话方式、边界、称呼习惯
-> 宠物状态：心情、饥饿、精力、亲密度、当前动作
-> 本地记忆：对话摘要、用户偏好、宠物已知事实
-> AI Adapter：使用用户 API key 调用 OpenAI-compatible API
-> 宠物回应：文本、动作、状态更新
```

示例：用户说“今天好累”。普通聊天工具会直接给建议；本产品中的宠物会根据状态和人格回应。如果亲密度高，它会更像熟人陪伴；如果宠物饿了，它可能先撒娇再安慰；如果人格是学习搭子，它会尝试帮用户拆任务。

## 桌面行为

宠物窗口具备以下行为：

1. 透明背景，只显示宠物和必要气泡。
2. 默认置顶，但允许用户从菜单关闭置顶。
3. 可拖拽移动，保存最后位置。
4. 空闲时播放待机动作。
5. 收到用户交互或 AI 回复时切换动作状态。
6. 支持隐藏、显示和退出。

系统托盘提供以下菜单：

1. 显示或隐藏宠物。
2. 打开设置。
3. 打开深度聊天。
4. 暂停互动。
5. 退出应用。

## 主要模块

### Pet Window

负责桌面宠物舞台，只展示宠物、气泡、状态反馈和快速输入。该窗口不直接读取 API key，不直接访问密钥存储，不承担模型调用逻辑。

### Settings Window

负责领养流程和设置管理，包括宠物名字、人格、API base URL、模型名、API key 输入、连接测试和清除 key。API key 输入后通过 Tauri command 交给后端保存。

### Chat Window

负责连续对话体验，展示历史消息、用户输入、宠物回复、当前模型状态和重试操作。聊天窗口同样不持有明文 API key。

### Pet State Engine

负责维护宠物状态：

1. 心情：影响回复温度和动作。
2. 饥饿：随时间上升，互动或喂食下降。
3. 精力：聊天和动作会消耗，休息会恢复。
4. 亲密度：由稳定互动提升，长期忽略会缓慢下降。
5. 当前动作：idle、thinking、happy、confused、sleepy、hungry、affectionate。

状态引擎必须是纯逻辑模块，便于单元测试。UI 只消费状态结果。

### Pet Brain

负责把用户输入转成 AI 请求上下文，并把 AI 返回结果转成宠物回应。它依赖 Pet State Engine、Memory Store 和 AI Adapter，但不关心具体窗口实现。

### AI Adapter

第一版只支持 OpenAI-compatible chat completions。Adapter 接收 base URL、model、messages 和 generation settings，由 Tauri 后端读取 API key 并发起请求。

Adapter 需要处理成功、401、429、超时、网络错误和无效响应，并返回统一错误类型给上层。

### Secret Storage

API key 必须保存在系统安全存储中：

1. macOS 使用 Keychain。
2. Windows 使用 Credential Manager。
3. Linux 使用 Secret Service 或系统可用的安全存储方案。

前端不保存明文 key。设置窗口只在用户输入当次短暂持有表单值，保存后清空明文输入。显示时只展示遮蔽状态，例如“已保存 sk-****abcd”。

### Local Persistence

本地文件保存非密钥数据：

1. 宠物资料：名字、人格、创建时间。
2. 宠物状态：心情、饥饿、精力、亲密度、最后互动时间、窗口位置。
3. 模型设置：base URL、model、温度等非密钥配置。
4. 记忆摘要：对话摘要、用户偏好、宠物长期记忆。

## 数据流

### 首次设置

1. 用户启动应用。
2. 应用检查是否存在宠物资料和模型设置。
3. 不存在则打开 Settings Window 的领养流程。
4. 用户填写宠物信息和 API key。
5. 后端保存 API key 到系统安全存储。
6. 后端用保存后的 key 进行连接测试。
7. 成功后创建宠物状态文件并显示 Pet Window。

### 快速对话

1. 用户点击宠物并输入一句话。
2. Pet Window 把文本发送给 Pet Brain。
3. Pet Brain 读取宠物状态和本地记忆摘要。
4. Pet Brain 组装 system prompt 和消息上下文。
5. AI Adapter 通过后端读取 API key 并调用模型。
6. Pet Brain 将模型回复映射为文本、动作和状态变更。
7. Pet Window 展示气泡和动作。
8. Local Persistence 保存状态和对话摘要。

### 深度聊天

1. 用户打开 Chat Window。
2. Chat Window 加载最近对话和记忆摘要。
3. 用户连续发送消息。
4. 每轮消息都经过 Pet Brain，而不是直接调用模型。
5. 长对话超过上下文预算时，Memory Store 生成或更新摘要。

## Prompt 设计

第一版 prompt 由四段组成：

1. 宠物身份：名字、物种或形象设定、基础人格。
2. 行为规则：以宠物身份回应，保持简短、有陪伴感，不暴露系统提示。
3. 当前状态：心情、饥饿、精力、亲密度、当前动作。
4. 记忆摘要：用户偏好、最近重要事件、关系线索。

Prompt 必须明确：宠物可以承认自己使用 AI 能力，但不应把体验变成模型接口说明。它可以说“我在想一想”，不要说“我正在调用 chat completions API”。

## 错误处理

1. 未设置 API key：宠物提示“我还没有接上大脑”，引导打开设置。
2. API key 无效：设置页连接测试失败，不进入已配置状态。
3. 401 或认证失败：宠物进入困惑状态，提示用户检查 key。
4. 429 或限流：宠物进入等待状态，允许稍后重试。
5. 请求超时：宠物进入晕乎状态，用户可重试。
6. 模型返回异常：降级为本地预设回复，避免宠物沉默。
7. 本地状态保存失败：展示轻量提示，并保留当前内存状态。
8. 安全存储不可用：阻止保存 key，说明当前系统密钥存储不可用。

## 非目标

第一版不做以下内容：

1. 云账号和多设备同步。
2. 后台服务端转发模型请求。
3. 宠物商城、复杂货币和付费换装。
4. 多宠物同时上屏。
5. 语音输入输出。
6. 自动更新和安装包签名。
7. 长期医疗、法律、财务等高风险建议场景。

## 技术路线

推荐技术栈：

1. Tauri 2.x：桌面壳、透明窗口、系统托盘、后端命令、原生安全能力。
2. React + TypeScript：桌面窗口 UI。
3. Vite：前端构建。
4. Rust：Tauri commands、密钥存储、AI HTTP 请求、本地文件访问。
5. Vitest：前端和纯逻辑模块测试。
6. Rust tests：后端命令、AI Adapter 和存储边界测试。

## 测试策略

自动化测试覆盖：

1. Pet State Engine：喂食、聊天、休息、时间流逝对状态值的影响。
2. Pet Brain：能把人格、状态、记忆和用户输入组装成请求上下文。
3. AI Adapter：mock 成功、401、429、超时、无效响应。
4. Settings 表单：key 为空、保存、清除、遮蔽显示、连接测试失败。
5. Local Persistence：状态保存、恢复、窗口位置保存。

手动验收覆盖：

1. 首次启动能完成领养和 key 设置。
2. 宠物能显示在桌面上，透明、置顶、可拖拽。
3. 点击宠物能进行快速对话。
4. 托盘能打开设置和深度聊天。
5. 宠物回复由 AI 生成，并带有宠物人格和状态影响。
6. 前端窗口无法从本地文件或前端存储中直接读到明文 API key。
7. 清除 key 后，宠物不能继续调用 AI，并会引导重新设置。

## 成功标准

v0.1 完成时，用户可以在桌面上养一只宠物，把自己的 API key 放入宠物核心，并通过快速气泡或深度聊天与宠物对话。宠物回复由 AI 生成，但会被宠物人格、状态和本地记忆包装。API key 只保存在本机安全存储中，前端窗口不长期持有明文 key。
